dbt-horizon: Snowflake dbt on DuckDB over Iceberg

The same dbt project Snowflake runs, executed by DuckDB in a container. It reads the source Iceberg tables and writes the marts back as Snowflake-managed Iceberg tables, through the Horizon catalog. No Snowflake warehouse runs the transformations, and the dbt repo is never edited.

1 · SYSTEM

Where code, data and credentials flow

The catalog only handles metadata: table lists, snapshots and commits. The data files move directly between DuckDB and S3, using short-lived credentials that Snowflake vends per table.

2 · DATA TRIGGER

What gets rebuilt when a source table changes

A table is stale when it doesn't exist yet, or when any source it reads, directly or through other models, has an Iceberg snapshot newer than the table's own. No state is stored; every check works it out again from snapshot times.

One check, step by step

  • Fetch the repo; new commits on main apply from this check on.
  • Read the latest snapshot time of every source (reader role) and every mart table (writer role, read-only). Metadata only; about a minute end to end with dbt parse.
  • Build the stale tables, everything downstream of them, and the views and seeds they read.
  • Check again: data committed during the build starts another pass, up to 3.

Ways to run it

  • watch --interval 900: a loop, as in the Docker Compose setup on this laptop.
  • watch --once: one check, for EventBridge, cron or a systemd timer.
  • --dry-run lists what is stale without building; --full rebuilds everything.
  • Code changes are not data changes: build after merges through CI, or run a nightly --full.

4 · FIVETRAN INGESTION

Two ways to get Fivetran data into Horizon

Fivetran can't write the Snowflake-managed Iceberg tables Horizon serves today. The two paths differ by one hop: whether Snowflake compute copies the data into Iceberg (A), or Fivetran writes Iceberg itself (B).

6 · ACCESS

Least privilege, by design

Two Snowflake roles, each able to do exactly one thing. A mistake in a model can't overwrite a source table, because the role that writes can't see the sources.
